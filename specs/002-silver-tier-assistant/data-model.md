# Data Model: Silver Tier — Functional Assistant

**Branch**: `002-silver-tier-assistant` | **Date**: 2026-02-12
**Source**: spec.md Key Entities + research.md decisions
**Extends**: Bronze Tier data-model.md (Vault Item, Dashboard, Company Handbook, Watcher State carried forward)

## Entity: Vault Item (Extended)

A Markdown file representing an actionable item in the vault. Extended from Bronze with new `type` values.

**Location**: `/Needs_Action/<filename>.md` (pending) or `/Done/<filename>.md` (processed)

**Filename convention**: `<type>-<timestamp>-<slug>.md`
- Example (Bronze): `email-20260212T143022-meeting-invite.md`
- Example (Silver): `whatsapp-20260212T160500-urgent-delivery.md`

### Frontmatter Fields (YAML)

| Field | Type | Required | Description | New in Silver |
|-------|------|----------|-------------|---------------|
| `type` | string | Yes | Source type: `email`, `whatsapp`, `file`, `manual` | `whatsapp` added |
| `from` | string | Yes | Sender or origin (e.g., email address, phone/contact name) | |
| `subject` | string | Yes | Subject line or title (for WhatsApp: first 50 chars of message) | |
| `date` | string (ISO 8601) | Yes | Date received | |
| `status` | string | Yes | `pending`, `done`, `planned`, `action_required` | `planned`, `action_required` added |
| `suggested_actions` | list of strings | No | AI-generated action suggestions | |
| `source_id` | string | Yes | Unique identifier from source (Gmail ID or WhatsApp msg hash) | |
| `processed_date` | string (ISO 8601) | No | Date the item was processed by the agent | |
| `priority` | string | No | `high`, `normal`, `low` | NEW |
| `classification` | string | No | `simple`, `complex`, `action_required` | NEW |
| `linked_plan` | string | No | Filename of associated Plan.md (if complex) | NEW |

### Body

Plain text content snippet (first 500 characters). For WhatsApp: full message text (typically shorter than emails).

## Entity: Plan Item

A Markdown file with checkbox steps for a complex multi-step task. Generated by the reasoning loop when an item is classified as "complex."

**Location**: `/Needs_Action/plan-<timestamp>-<slug>.md`

**Filename convention**: `plan-<timestamp>-<slug>.md`
- Example: `plan-20260212T163000-q1-report-preparation.md`

### Frontmatter Fields (YAML)

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | string | Yes | Always `plan` |
| `linked_item` | string | Yes | Filename of the original vault item that triggered this plan |
| `status` | string | Yes | `in_progress` or `complete` |
| `priority` | string | Yes | `high`, `normal`, `low` (inherited from linked item) |
| `created_date` | string (ISO 8601) | Yes | Date plan was generated |
| `completed_date` | string (ISO 8601) | No | Date all steps were checked off |
| `total_steps` | integer | Yes | Number of checkbox steps |
| `completed_steps` | integer | Yes | Number of checked steps |

### Body

Markdown checkbox list with actionable steps.

### Example

```markdown
---
type: plan
linked_item: email-20260212T143022-q1-budget-review.md
status: in_progress
priority: high
created_date: 2026-02-12T16:30:00Z
total_steps: 4
completed_steps: 0
---

# Plan: Q1 Budget Review Preparation

**Original item**: email-20260212T143022-q1-budget-review.md
**From**: boss@company.com

## Steps

- [ ] Review attached Q1 budget document
- [ ] Gather department spending data from finance team
- [ ] Draft summary comparing spending vs. projections
- [ ] Send summary to team for review (→ creates approval draft)

## Notes

- Step 4 will generate an approval draft in /Pending_Approval when ready
- Finance team contact: finance@company.com
```

### State Transitions

```text
[Complex item detected]
    │
    ▼
[Plan.md created] (status: in_progress, 0/N steps)
    │
    ▼
[User checks off steps in Obsidian]
    │
    ▼
[All steps checked] → (status: complete) → moved to /Done
```

## Entity: Approval Draft

A Markdown file in `/Pending_Approval` representing a proposed external action awaiting human consent.

**Location**: `/Pending_Approval/<action-type>-<timestamp>-<slug>.md`

**Filename convention**: `<action-type>-<timestamp>-<slug>.md`
- Example: `email-send-20260212T170000-reply-to-boss.md`
- Example: `mastodon-post-20260212T180000-q1-update.md`

### Frontmatter Fields (YAML)

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | string | Yes | `email-send`, `mastodon-post` |
| `target` | string | Yes | Recipient (email address) or platform (`mastodon`) |
| `status` | string | Yes | `pending`, `approved`, `rejected`, `executed`, `failed` |
| `created_date` | string (ISO 8601) | Yes | Date draft was created |
| `approved_date` | string (ISO 8601) | No | Date user checked the approval box |
| `executed_date` | string (ISO 8601) | No | Date action was executed by MCP |
| `linked_item` | string | No | Original vault item or plan that triggered this draft |
| `mcp_tool` | string | Yes | MCP tool name to invoke (`email_send` or `mastodon_post`) |

### Body

The draft content followed by approval checkboxes.

### Example (Email Send)

```markdown
---
type: email-send
target: boss@company.com
status: pending
created_date: 2026-02-12T17:00:00Z
linked_item: plan-20260212T163000-q1-report-preparation.md
mcp_tool: email_send
---

# Draft: Reply to Q1 Budget Review

**To**: boss@company.com
**Subject**: Re: Q1 Budget Review Meeting

## Content

Hi,

I've reviewed the Q1 budget document. Here's a summary of our
department's spending vs. projections:

- Marketing: $45K spent vs. $50K projected (10% under)
- Engineering: $120K spent vs. $115K projected (4% over)
- Operations: $30K spent vs. $32K projected (6% under)

Overall we're tracking within 2% of the total budget. Happy to
discuss further at Friday's meeting.

Best regards

## Approval

- [ ] Approved
- [ ] Rejected

> Edit the content above before approving if needed.
> Check "Approved" to send, or "Rejected" to cancel.
```

### Example (Mastodon Post)

```markdown
---
type: mastodon-post
target: mastodon
status: pending
created_date: 2026-02-12T18:00:00Z
linked_item: null
mcp_tool: mastodon_post
---

# Draft: Social Media Post

**Platform**: Mastodon
**Visibility**: public

## Content

Excited to share our Q1 results! Our team delivered 15% above
target while staying within budget. Building great things with
AI-assisted workflows.

#business #AI #productivity #Q1results

## Approval

- [ ] Approved
- [ ] Rejected

> Edit the content above before approving if needed.
```

### State Transitions

```text
[Action-required item detected]
    │
    ▼
[Draft created in /Pending_Approval] (status: pending)
    │
    ├── User checks "Approved" → (status: approved)
    │       │
    │       ▼
    │   [Approval checker triggers MCP tool]
    │       │
    │       ├── Success → (status: executed) → moved to /Done
    │       └── Failure → (status: failed) → moved to /Done with error
    │
    └── User checks "Rejected" → (status: rejected) → moved to /Done

[>24 hours without action] → Flagged in Dashboard as "awaiting approval"
```

## Entity: MCP Action Log

A record of every external action executed by the MCP server.

**Location**: `/Logs/mcp-<timestamp>-<tool-name>.md`

**Filename convention**: `mcp-<timestamp>-<tool-name>.md`
- Example: `mcp-20260212T170500-email-send.md`

### Frontmatter Fields (YAML)

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | string | Yes | Always `mcp_action` |
| `tool` | string | Yes | MCP tool name (`email_send`, `mastodon_post`) |
| `result` | string | Yes | `success` or `failure` |
| `error_message` | string | No | Error details (if result is `failure`) |
| `timestamp` | string (ISO 8601) | Yes | When the action was executed |
| `linked_draft` | string | Yes | Filename of the approval draft that triggered this action |
| `parameters` | object | Yes | Tool parameters (sanitized — no passwords) |

### Example

```markdown
---
type: mcp_action
tool: email_send
result: success
timestamp: 2026-02-12T17:05:00Z
linked_draft: email-send-20260212T170000-reply-to-boss.md
parameters:
  to: boss@company.com
  subject: "Re: Q1 Budget Review Meeting"
---

# MCP Action Log: email_send

**Tool**: email_send
**Result**: ✅ Success
**Time**: 2026-02-12 17:05:00

Email sent successfully to boss@company.com.
```

## Entity: Schedule Configuration

Settings defining when and how often each component runs.

**Location**: `src/scheduling/scheduler_config.json`

### Schema

```json
{
  "interval_minutes": 5,
  "components": {
    "gmail_watcher": {
      "enabled": true,
      "vault_path": "./vault",
      "credentials": "./credentials.json"
    },
    "whatsapp_watcher": {
      "enabled": true,
      "vault_path": "./vault",
      "session_path": "~/.whatsapp_session"
    },
    "reasoning_loop": {
      "enabled": true,
      "vault_path": "./vault"
    },
    "approval_checker": {
      "enabled": true,
      "vault_path": "./vault"
    }
  },
  "last_run": "2026-02-12T17:00:00Z",
  "log_path": "./vault/Logs"
}
```

### Rules

- `interval_minutes` defines the schedule frequency (default: 5).
- Each component can be individually enabled/disabled.
- `last_run` is updated after every successful cycle.
- Configuration changes take effect on the next scheduled cycle.

## Entity: Watcher State (Extended)

Extended from Bronze to support per-watcher state files.

**Location**: `<vault_root>/.watcher_state_<source>.json`
- Gmail: `.watcher_state_gmail.json`
- WhatsApp: `.watcher_state_whatsapp.json`

### Schema (WhatsApp)

```json
{
  "source": "whatsapp",
  "last_poll": "2026-02-12T16:05:00Z",
  "processed_ids": [
    "hash_abc123def456",
    "hash_789ghi012jkl"
  ]
}
```

### Rules

- Same rules as Bronze (10,000 ID cap, oldest removed first).
- WhatsApp message IDs are hashes of `sender + timestamp + first 100 chars`.
- Each watcher has its own independent state file — no cross-contamination.
- Bronze migration: Rename `.watcher_state.json` → `.watcher_state_gmail.json` on first Silver run.

## Entity Relationships (Silver)

```text
Watcher State (gmail) ──tracks──> Vault Items (type: email)
Watcher State (whatsapp) ──tracks──> Vault Items (type: whatsapp)
Vault Items ──classified by──> Classifier
  ├── simple ──processed──> /Done
  ├── complex ──generates──> Plan Item
  └── action_required ──generates──> Approval Draft
Plan Item ──linked to──> Vault Item (via linked_item)
Plan Item ──may generate──> Approval Draft (for action steps)
Approval Draft ──approved by──> Human (Obsidian checkbox)
Approval Draft ──triggers──> MCP Tool (via mcp_tool field)
MCP Tool ──logs──> MCP Action Log
Dashboard ──summarizes──> All entities
Company Handbook ──read by──> Reasoning Loop + Social Post Generator
Schedule Config ──controls──> All watchers + reasoning + approval checker
```

## Full State Transition Diagram

```text
[Message arrives (Gmail/WhatsApp)]
    │
    ▼
[Watcher polls] ──creates──> Vault Item (status: pending, in /Needs_Action)
    │
    ▼
[Watcher State updated] ──records──> source_id
    │
    ▼
[Reasoning Loop invoked (scheduled or manual)]
    │
    ├──reads──> Company Handbook (for rules)
    ├──reads──> Vault Item (from /Needs_Action)
    │
    ▼
[Classifier determines type]
    │
    ├── SIMPLE ──writes──> Report in /Done (Bronze behavior)
    │                └──updates──> Dashboard.md
    │
    ├── COMPLEX ──writes──> Plan.md in /Needs_Action
    │                ├──updates──> Vault Item (status: planned)
    │                └──updates──> Dashboard.md (Active Plans)
    │
    └── ACTION_REQUIRED ──writes──> Approval Draft in /Pending_Approval
                     ├──updates──> Vault Item (status: action_required)
                     └──updates──> Dashboard.md (Pending Approvals)

[Approval Checker invoked (scheduled or manual)]
    │
    ├──reads──> /Pending_Approval files
    │
    ├── APPROVED (checkbox checked)
    │       ├──invokes──> MCP Tool (email_send or mastodon_post)
    │       ├──writes──> MCP Action Log in /Logs
    │       ├──moves──> Draft to /Done (status: executed)
    │       └──updates──> Dashboard.md
    │
    ├── REJECTED (checkbox checked)
    │       ├──moves──> Draft to /Done (status: rejected)
    │       └──updates──> Dashboard.md
    │
    └── PENDING (no action taken)
            └── If >24 hours: flag in Dashboard as "awaiting approval"
```
